What was repaired

  1. Case isolation. Each case has its own collection state. A resume with a different case or scope is rejected.
  2. Crawl continuity. Pending URLs, retries, visited URLs and cumulative hashes persist between runs.
  3. Complete captures. Oversized, empty and truncated responses are rejected before preservation.
  4. Redirect boundaries. Redirect destinations must stay within approved hosts. HTTPS downgrades are refused.
  5. Source identity. URL paths, query values and trailing slashes retain their meaning.
  6. Integrity checks. Preserved evidence references are checked for file existence and SHA-256 consistency.
  7. Site links. Both broken local links were repaired, including the catalogue generator.
  8. Publication checks. The custom deployment workflow checks new validation errors against an explicit inventory. A separate GitHub Pages publication route was found outside that gate; sole-route enforcement remains unresolved.

What remains open

Some historical records lack source metadata or supporting evidence, use inconsistent classifications, or identify a source instead of a preserved file. One note identifier is duplicated. These require record-level corrections that retain the original history.

Missing change registers have been initialized with this repair entry. Earlier history has not been invented.

The collection agent’s upstream access blocks are also unresolved. A rejected request does not prove that evidence is absent.

No clean bill of health.

The strict validator still fails. The publication check permits only the explicitly recorded existing failures and displays them here. It rejects additional failures. Code regression tests passing does not make the evidence validated.
